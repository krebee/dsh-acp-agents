# DSH ACP Agents

[日本語](README.md) · [简体中文](README.zh-CN.md) · [English](README.en.md)

**普段使っているコーディングエージェントを DeepSeek Harness と Whale Isle（鯨嶼）に接続し、直接の会話や管理されたサブエージェントとの連携に活用できます。**

Claude Code、OpenAI Codex、Google Antigravity、Cognition Devin、および [Agent Client Protocol（ACP）](https://agentclientprotocol.com/) に対応したその他のサービスを利用できます。アカウント、モデル、実行設定は **設定 → Agent** で一元管理し、会話画面下部のエージェント別セレクターでエージェント、モデル、推論レベルを選択できます。

[リリース・ダウンロード](https://github.com/ChisaAlter/dsh-acp-agents/releases) · [問題を報告する](https://github.com/ChisaAlter/dsh-acp-agents/issues) · [ライセンス](LICENSE)

## 主な機能

- **同じ会話内でエージェントを切り替える**：ホスト側の会話 ID を維持したまま、表示されているコンテキストを選択先に引き継ぎます。元のエージェントに戻ると、既存の ACP セッションを再利用できます。
- **他のエージェントにタスクを委譲する**：ツールを通じて独立した子セッションを開始し、完了時に結果を自動で受け取れます。
- **Agent Teams に参加する**：設定済みのエージェントをリーダーやチームメンバーとして利用し、ホスト標準のメンバーと同じタスクボードを共有できます。
- **バックグラウンドタスクの状況を確認する**：最近の活動、実行中のツール、回答・承認待ち、実際の完了・失敗・キャンセル結果を確認できます。
- **複数のアカウントを管理する**：同じ種類のエージェントについて、アカウントディレクトリ、環境変数、モデル設定が異なる複数のインスタンスを作成できます。

本リポジトリは、ACP ランタイムを同梱する独立した Cordis プラグインです。Whale Isle や DeepSeek Harness のホスト本体は含まれていません。

## インストールと初期設定

### 1. プラグインのインストール

[GitHub Releases](https://github.com/ChisaAlter/dsh-acp-agents/releases) から必要なバージョンの `.tgz` プラグインパッケージをダウンロードし、そのファイルがあるディレクトリで次のコマンドを実行します。

```sh
dsh plugin --profile web add "./dsh-acp-agents-<version>.tgz"
```

`<version>` はダウンロードしたファイルの実際のバージョンに置き換えてください。`web` には実際に使用するプロファイルを指定します。Whale Isle が管理するプロファイルでは、Whale Isle に同梱された CLI を使用してください。アップデート前にホストを正常終了し、インストール後に再起動します。プラグインは GitHub から配布されており、npm レジストリからはインストールしません。

**現在のソースコードをパッケージ化する場合**は、同梱ランタイムを再ビルドせずに利用できます。

```sh
git clone https://github.com/ChisaAlter/dsh-acp-agents.git
cd dsh-acp-agents
npm pack
dsh plugin --profile web add ./dsh-acp-agents-0.4.9.tgz
```

現在のソースパッケージのバージョンは **0.4.9** です。リリースページの配布ファイルは、それぞれのタグに対応します。

### 2. アカウントの設定

1. **設定 → Agent** を開き、インスタンスを追加または選択します。
2. ログインするか、そのエージェントに必要な API 認証情報、コマンド、環境変数を入力します。
3. 接続をテストし、モデルを同期してからインスタンスを有効にします。
4. 会話画面に戻り、セレクターでエージェント、モデル、利用可能な推論レベルを選択します。

エージェントの有効・無効スイッチは、モデル選択とタスク実行の可否だけを制御します。無効化や再有効化でログアウトすることはなく、確認済みのログイン状態は再読み込みや再起動後も保持されます。アカウントからログアウトするには **ログアウト（Sign out）** を使用してください。

Claude Code、Codex、Antigravity は ACP Registry が管理する配布形式に対応し、Devin はローカルの CLI を使用します。他の ACP サービスでは、起動コマンド、引数、環境変数を設定できます。ターミナル経由のログインにはホストの PTY サービスが必要ですが、その他のログイン方式はこのサービスに依存しません。

通常のログインでは、既存の認証情報でセッションを作成できるかを最初に確認し、不要な再認証を避けます。アカウントを変更する場合は **切り替え／再ログイン（Switch / Sign in again）** を使用します。ブラウザーが開いただけではログイン成功とはみなさず、実際に ACP セッションを作成して認証状態を確認します。キャンセルや有効期限切れの場合は、ログイン用プロセスを解放します。

モデル、推論レベル、選択式・真偽値のオプション、認証情報の入力フォームは ACP のケイパビリティに基づいて検出されます。推論オプションを公開していないモデルでは、そのモデル自身の既定値を使用し、`medium` などの設定を追加で注入することはありません。明示的に選択したパラメーターは実行前に再検証されます。

## 会話内でエージェントを切り替える

別のエージェントを選択しても、ホスト側に新しい会話は作成されません。初回の切り替え時には、新しいエージェントに表示中の会話テキストが渡されます。使用済みのエージェントに戻るときは、その ACP セッションを維持したまま、不在中のターンが補われます。

- コンテキストの引き継ぎには表示中のテキストと保持された画像が含まれます。他のエージェントの非公開の推論や内部実行状態は含まれません。
- 画像は ACP の画像対応能力をネゴシエーションした後、実際のバイトデータとして転送されます。テキスト専用と判明している接続先では画像が省略されたことを明示し、能力のネゴシエーションが完了していない画像の処理経路ではエラーを返します。ファイルはリソースリンクとして渡されます。ホストが読み取り可能な保存先パスとして提供する場合もあります。
- ネイティブセッションの復元に失敗した場合は、既存のマッピングを保持してエラーを報告します。黙って代替セッションを作成することはありません。

履歴を伴う会話の切り替えは、ホスト側のコンテキスト管理機能にも依存します。[互換性と動作要件](#互換性と動作要件)を参照してください。

## サブエージェントにタスクを委譲する

プラグインはホストのモデル向けにツールを登録し、セッション認証付きの MCP ブリッジを通じて外部エージェントにも提供します。親エージェントは、自身のモデルを切り替えずに他の有効なエージェントにタスクを委譲できます。

### エージェントを検索してタスクを開始する

まず `acp_agents()` を呼び出して実際のインスタンス ID とモデル ID を取得し、次に `acp_delegate` を呼び出します。例えば、インスタンス ID が `codex` の場合は次のように指定します。

```json
{
  "agent": "codex",
  "description": "セッションのキャンセル処理をレビューする",
  "prompt": "lib/acp-session.js のキャンセル処理における競合状態を読み取り専用で調査してください。ファイルは変更せず、具体的な指摘事項と行番号を返してください。",
  "client_request_id": "review-session-cancel-1"
}
```

サブエージェントは既定で作業ディレクトリを共有しますが、**親の会話内容は継承しません**。必要な目的、背景、権限の範囲を `prompt` に記載してください。タスク受付前に、接続、認証、モデル、パラメーターが検証されます。準備に失敗した場合、子タスクは作成されません。検証済みの接続は再利用され、準備段階ではタスクのプロンプトを送信しません。

受け付けられたタスクは `taskId`、`subagentId`、`status: "running"`、`next` を返します。親エージェントは `next` に従って現在のターンを終了し、結果を待ちます。完了結果は永続化されて通知されます。親が処理中なら次のモデル処理ステップで受け取り、待機中なら自動的に再開します。子エージェントが最終報告を重複して送信する必要はありません。

### タスクの確認・継続・キャンセル

| ツール | 用途 |
| --- | --- |
| `acp_agents()` | 有効なエージェントのインスタンスとモデルを一覧表示します。認証情報は返しません。 |
| `acp_delegate({ agent, prompt, ... })` | 独立したタスクを開始します。既定では非同期で返ります。 |
| `acp_result({ task_id })` | 指定タスクの状態と出力を取得します。過去のタスクも個別に参照できます。 |
| `send_message` | 既存の子セッションに入力を追加します。前のタスクが終了した後は、新しい実行記録を作成します。 |
| `interrupt_agent` | キュー内の入力を保持したまま、現在の実行を中断します。 |
| `acp_cancel({ task_id })` | タスクをキャンセルし、キューを空にして子孫タスクとリソースの解放を待ち、そのタスクの完了による再開通知を停止します。完了済みの出力は引き続き参照できます。 |

`acp_result` は完了通知を受け取った後、またはユーザーから状況確認を求められた場合に使用し、実行中のタスクをポーリングしないでください。互換性のためのパラメーター `agent_id` は、その子セッションの最新タスクを取得します。過去の結果を取得する場合は `task_id` を優先してください。

`acp_result.wait_ms` と委譲時の `mode: "wait"` は、いずれも最大 **20000 ms** のイベント駆動型の待機に対応します。待機がタイムアウトしても自動完了通知は維持されます。同じ `client_request_id` と同じパラメーターで再試行してもタスクは重複して開始されません。同じ ID に異なるパラメーターを指定するとエラーになります。

### オプションのパラメーター

- `model`、`reasoning_effort`：検索結果から取得した実際の ID を指定します。モデルを省略した場合は、表示対象の設定済みモデルの先頭が使用されます。
- `options: [{ "id": "…", "value": "…" }]`：モデルが公開する権限設定以外のオプションを指定します。値には文字列または真偽値を使用できます。
- `isolation: "worktree"`：コミット済みの `HEAD` から独立した作業ツリーを `.agent-worktrees/` 配下に作成し、保持されたパスを結果に返します。未コミットの変更はコピーされず、親の作業領域のファイルを移動・削除することもありません。このディレクトリはリポジトリの `.git/info/exclude` に追加されます。
- `interaction_mode: "plan"`：読み取り専用の調査・計画に制限します。
- `runtime_mode`：`inherit`、`read-only`、`approval-required` のいずれかを指定します。ホストの権限を継承するか、さらに制限することだけが可能です。
- `mode: "wait"`、`timeout_ms`：上限付きの待機を指定します。既定では非同期で、待機時間の既定値は 15000 ms、最大値は 20000 ms です。
- `name`：任意のチームメンバー名です。小文字の英字、数字、ハイフンからなる 1～32 文字で、英字で始める必要があります。`lead` は使用できず、同じ親の下で一意である必要があります。

### バックグラウンド処理は後続の出力を妨げない

ネイティブのバックグラウンドツールが実行中の場合、活動状態は個別に報告されます。実際に完了または失敗した時点で初めて、ホスト側にツールの実行結果が記録されます。後続のテキストや完了済みの別のツールは、最初のバックグラウンドコマンドの終了を待つ必要がありません。ACP のネストされたテキストとエラー詳細もツール結果に保持されます。

タスクカードにはエージェント、モデル、タスク、状態、経過時間が表示され、クリックすると既存の子会話を開けます。ネイティブのターンで使用量の集計が完了するまでは、トークン使用量は **使用量の集計待ち（Usage pending）** と表示されます。稼働状態の判定には使用しません。

**5 分間ネイティブの活動がない場合**、カードに **5 分間更新なし（No update for 5 min）** と表示され、親エージェントにそのタスクについて一度だけ通知されます。ユーザーの回答・承認待ちは通知の対象外です。新しい活動があれば表示は解除されます。活動がないことを理由にプロセスを強制終了したり、自動で再試行したり、重複タスクを作成したりすることはありません。

ホストの再起動後に親会話を開くと、子会話の履歴と永続化された受信トレイを照合してタスク状態を調整し、未配信の結果を届けます。中断されたタスクには復旧に関する診断情報が表示され、明示的に新しい入力を追加した場合だけ再開します。元のプロンプトを自動で再実行することはありません。実行結果の記録がない旧バージョンのエントリは、引き続き履歴ログを利用して復旧時の表示を行います。

## Agent Teams を利用する

ルート会話のセレクターで **エージェントチームを使用（Use Agent Teams）** を有効にします。この設定は、設定済みの ACP エージェントを含むサブエージェントツリー全体に適用されます。

1. リーダーが `team_task_create` を呼び出し、目的、依存関係、想定する書き込み範囲を指定してタスクを作成します。
2. `acp_delegate` で名前付きのチームメンバーを作成し、指示に担当タスクの ID を含めます。
3. メンバーは `team_task_list` / `team_task_get` でタスクを確認し、最新のリビジョンを指定して `team_task_update` で担当を引き受け、完了時にステータスを更新します。
4. 他のメンバーの対応が必要な場合は `send_message` を使用します。タスクボードの更新だけではメンバーは再開しません。子タスクの完了は親に自動通知されます。

ACP エージェントとホスト標準のメンバーは、同じホストのタスクボードを利用します。担当を引き受ける権限、リーダーによる担当変更、リビジョンの検証は、実際の呼び出し元の識別情報に基づいてホストが実施します。`write_scopes` は連携のための情報であり、ファイルロックではありません。並行編集では、担当範囲が重複しないように分担してください。

チームモードが有効な場合、`list_agents` はチーム全体を返します。ルートの名前は `lead` で、メンバーには返されたパス形式の名前を使用し、呼び出し元には `self` が付与されます。`send_message` と `interrupt_agent` にはチーム内の名前またはセッション ID を指定できますが、中断権限は呼び出し元が作成したエージェントに限定されます。チームモードが無効な場合、一覧には直接の子エージェントのみが表示されます。登録済みの Team ツールが MCP のツール一覧に残る場合もありますが、呼び出すたびに現在の設定を確認し、無効時はタスクボードの変更を拒否します。

現在、設定済みの ACP リーダーが作成できるのは、設定済みの ACP チームメンバーです。ホスト標準の DSH モデルをチームメンバーとして作成する `subagent` ツールは、まだ公開されていません。

## 権限・データ・復旧

### 権限はホストが制御する

エージェントの設定によって追加の権限が付与されることはありません。ツール実行結果をホストに反映する処理と ACP の権限要求は独立しており、実行は現在のホストのサンドボックスと承認ポリシーに従います。人による確認が必要な操作には、ルート会話の質問インターフェースを使用します。明示的な `never` ポリシーでは、承認が必要な操作が拒否されます。承認待ち、質問への回答待ち、対話の失敗はそれぞれの状態として記録されます。

Antigravity の `yolo` など、エージェント独自の確認不要モードが有効になるのは、ホストが `danger-full-access` かつ承認ポリシーが `never` の場合だけです。`workspace-write` ではサンドボックスによる検査が引き続き適用されます。認証、ネットワーク、モデルのエラーは本来の原因に基づいて対処し、権限の要求を緩めて再試行することはありません。

### ローカルの保存先

データは `$DSH_HOME` 以下に保存されます。未設定の場合は `~/.dsh` が使用されます。

| パス | 内容 |
| --- | --- |
| `acp-agents.json` | エージェントのインスタンス、モデル、環境変数の設定。認証情報が含まれる場合があります。 |
| `acp-agent-sessions.json` | ホストセッションと外部 ACP セッションの対応関係。 |
| `acp-tasks.json` | 永続化されたタスクの実行記録。プロンプト、出力、再試行時の識別情報を含みます。 |
| `acp-profiles/` | 既定のアカウントディレクトリ。明示的な `profileDir` の指定が優先されます。 |
| `acp-error.log` | 機密情報をマスキングした診断ログ。1 MiB に達すると `.1` にローテーションされます。 |

これらのファイルは会話ログと同様に適切に保護してください。認証情報はローカル設定に保存されます。カタログの応答では機密情報と判定された値がマスキングされ、変更されていない値は保存時に元の値が保持されます。POSIX パーミッションに対応する環境では、ファイルの権限は `0600`、プラグインが所有するアカウント・キャッシュディレクトリの権限は `0700` に制限されます。ユーザーが指定した既存の `profileDir` の権限は変更しません。Windows のアクセス制御はローカルディレクトリの権限に従います。

アップグレード時には、インスタンス ID、`acp:<instance ID>` プロバイダー、アカウントディレクトリ、セッションのマッピング、既存のランタイムキャッシュが保持されます。明示的な `profileDir` の指定は、継承された、または競合するホームディレクトリ関連の環境変数より優先されます。明示的な上書き指定がない場合、Antigravity は既存のインスタンスディレクトリを引き続き使用し、新しい `agy acp` と旧サーバー起動方式の両方に対応します。

### 読み取れない保存ファイルを復旧する

解析できないファイルや構造が不正なファイルは、`<filename>.corrupt-<timestamp>` という名前で保全されます。その後、空のストアで起動するため、次回の保存で元のデータが上書きされることはありません。**設定 → Agent** には保全された各ファイルの場所が表示され、再起動後も確認できます。

保全されたファイルを修復して元のファイル名に戻す前に、ホストを停止して現在のファイルをバックアップしてください。保全ファイルを復元するか元のディレクトリから移動すると、該当する通知が消えます。タスクの実行記録は件数によって自動削除されないため、過去の結果と冪等性を確保する識別情報が保持されます。ストアの読み込み時に古い一時ファイルを経過時間で削除することはなく、書き込みに失敗した場合は、その書き込みで作成された一時ファイルのみを削除します。

## 互換性と動作要件

- Node.js `^22.19.0 || >=24.0.0`。
- Cordis 4、LLM アダプター登録機能、接続サービス、Web サービスを提供する DeepSeek Harness / Whale Isle ホスト。
- サブエージェントへの委譲には、ホストの `subagents`、`tools`、および管理されたローカル子セッションのインターフェースも必要です。これらのサービスがなくても、会話内のエージェント切り替えは利用できます。
- Agent Teams にはホストの Team サービスが必要です。Windows でのターミナルログインには、ホストが ConPTY を正しく解放できることが必要です。このプラグインのインストールだけではホストの PTY モジュールは更新されません。

**標準 DSH 0.2.2-rc.2：** ホスト標準の設定画面への導線と、ケイパビリティに基づく推論オプションは検証済みです。会話履歴を伴うモデル切り替えには、対応する[サーバー側のコンテキスト帰属の修正](tools/host-compat/README.md)が必要です。プラグインパッケージがホストのモジュールを自動で変更することはありません。

**DSH 0.2.2-rc.3：** 以前報告されたモデルを選択できない問題は、実行環境での検証待ちです。公開ソースにはコンテキスト容量が不明な場合の切り替え制限があるため、rc.2 用のサーバー側の修正を適用しないでください。

管理された委譲は、ホストの subagent 0.2.1 のネスト形式のリクエストと、0.2.2 のフラット形式のリクエストに対応します。すでに受理されている可能性がある委譲を再試行することはありません。通常の子タスクの一覧、状態確認、待機、継続入力の権限は直接の親子関係に限定されます。MCP の所有権は現在の実行に使用されるプロバイダーの接続先に追従します。

## 開発と検証

### 同梱ランタイムの再ビルド

ランタイムのソースを変更した場合のみ再ビルドが必要です。

```sh
npm ci --prefix tools/runtime-build
npm run build:runtime
```

ランタイムのソーススナップショットと選択された上流コードの上書き内容は `tools/runtime-build/upstream/SOURCE.json` に記録されています。ビルドは他のプロジェクトのチェックアウトや T3 Code のインストールに依存しません。プラグインはアカウント管理、セッションルーティング、ホストとの連携、UI を担当します。改変したサードパーティーコードはランタイムディレクトリに分離されています。出典とライセンスについては [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) を参照してください。

### 変更範囲に応じた検証

```sh
npm test
```

追加の統合テストでは、必要に応じてホストのパスを指定します。

| コマンド | 前提条件と検証範囲 |
| --- | --- |
| `npm run test:client` | `DSH_CLIENT_HOST_ROOT` に、`package.json` を含む対応ホストのパッケージディレクトリを指定します。実際の Cordis の有効化とクライアント互換性を検証します。 |
| `npm run test:host` | `DSH_HARNESS_ROOT` に、開発用 testkit を含むビルド済みの Harness を指定します。AgentLoop、子セッション、ACP プロセス、HTTP/MCP ブリッジを検証します。 |
| `npm run test:team` | 同じ `DSH_HARNESS_ROOT` を使用し、`packages/team` のビルドが必要です。本番ホストの依存関係を使用して共有タスクボードとメンバー間の連携を検証します。開発用 testkit は不要です。 |
| `npm run test:installed-host` | `DSH_INSTALLED_HOST_ROOT` に、デスクトップアプリのインストール先にある `resources/vendor/deepseek-harness` を指定します。隔離されたセッションで委譲、バックグラウンド進捗、切り替え、継続入力、過去の結果、キャンセル、活動停止通知を検証します。 |
| `npm run test:host-compat` | `DSH_COMPAT_HOST_PACKAGE` に、対応ホスト CLI の `package.json` を指定します。サーバー側の変換処理、通常の LLM の容量制限、非対応バージョンの拒否、準備用ディレクトリのクリーンアップを検証します。インストール済みホストは変更しません。 |

通常の統合テストはスクリプトで模擬した ACP サービスを使用し、有料モデルへのリクエストや実際のアカウントは使用しません。`test:installed-host` で実際のアカウントを検証する場合は、`DSH_NATIVE_HOME` と `DSH_TEST_NATIVE_AGENT` を明示的に設定し、必要に応じて `DSH_TEST_NATIVE_MODEL` を指定します。指定されたネイティブアカウントを再利用して短い応答を取得するだけで、ログイン処理を開始したり、普段使用しているエージェント、セッションのマッピング、タスクの JSON ファイルを書き換えたりすることはありません。
